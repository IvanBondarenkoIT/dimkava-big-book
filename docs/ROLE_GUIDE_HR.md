## HR guide — что делать и где смотреть

### Основные задачи HR в портале
- **Кандидаты**: дать доступ, следить за прогрессом/результатами, конвертировать в сотрудника.
- **Контент**: отметить что “видно кандидатам”, поддерживать актуальность курсов/онбординга.
- **Онбординг**: назначить правильную программу (через профили/правила), проверить завершение.

---

### Как обновлять и дополнять контент (кто и как)

Сейчас есть **2 способа**:

1) **Через админку (ручной режим)** — основной способ для HR
- **Кто делает**: HR (и/или директор/контент-менеджер), при необходимости — админ.
- **Когда использовать**: быстро поправить текст, переименовать, включить флаги видимости, поменять порядок, добавить вопрос в квиз.
- **Где**:
  - Курсы/уроки/вопросы: `Courses → Courses / Lessons / Test questions`
  - Онбординг: `Onboarding → Programs / Modules / Steps`
  - База знаний: `Knowledge base → Sections / Articles`
  - Новости: `News → News posts`

2) **Через YAML-команды (массовый импорт/обновление)** — обычно делает админ/разработчик
- **Кто делает**: Admin / разработчик (реже HR, если уверенно с командами).
- **Когда использовать**: массово обновить структуру контента из `input/hr docs/content`, переимпортировать демо-набор.
- **Команды**:
  - `python manage.py load_onboarding`
  - `python manage.py load_courses`
  - `python manage.py load_articles`
  - `python manage.py load_news`
  - `python manage.py load_departments` (после `load_courses`)

Важно:
- Если база “пустая”, команда `python manage.py create_default_users` **сама загрузит** демо-контент (если не передан `--no-seed`).
- Для кандидатов не забывайте выставлять `visible_for_candidates=True` у нужных программ/курсов/уроков.

---

### Быстрый workflow контента (рекомендуемый)

#### A) Добавить/обновить курс с тестированием (через админку)
1. `Courses → Courses` → **Add**
   - `status=published` (иначе не увидят пользователи)
   - если курс нужен кандидатам: **`visible_for_candidates=True`**
2. `Courses → Lessons` → добавить уроки
   - для каждого урока, который нужен кандидатам: **`visible_for_candidates=True`**
3. Если нужен квиз:
   - урок `lesson_type=quiz`
   - `Courses → Test questions` → добавить вопросы к этому quiz-уроку
4. Проверка:
   - зайти под кандидатом → `/courses/` → курс виден
   - открыть квиз → должен открываться (если курс+урок помечены для кандидатов)

#### B) Добавить/обновить онбординг (через админку)
1. `Onboarding → Onboarding programs`
   - если программа для кандидатов: **`visible_for_candidates=True`**
2. `Onboarding → Onboarding modules / steps`
   - порядок модулей и шагов влияет на прогресс и UI
3. Проверка:
   - зайти под кандидатом → `/onboarding/` → программа видна и прогресс считается

#### C) Обновить базу знаний / новости
1. `Knowledge base → Sections / Articles` (статьи)
2. `News → News posts` (новости)
3. Быстрая проверка: открыть страницы `/wiki/` и `/news/` под нужной ролью

---

### Мини-чеклист “перед тем как дать кандидатам ссылку”
- У программы онбординга стоит **`visible_for_candidates=True`**
- У нужных курсов стоит **`visible_for_candidates=True`**
- У нужных уроков (включая quiz-урок) стоит **`visible_for_candidates=True`**
- Под кандидатом реально открывается:
  - `/onboarding/`
  - `/courses/` и 1–2 ключевых урока/квиза

---

### Навигация (где всё находится)
- **Админка**: `/admin/`
- **Кандидаты/пользователи**: `Accounts → User profiles` (это основной экран HR)
- **Правила назначения**: `Accounts → Assignment rules`
- **Онбординг**:
  - `Onboarding → Onboarding programs`
  - `Onboarding → Onboarding modules / steps`
  - `Onboarding → Mentor assignments / sessions` (если используете менторство)
- **Курсы/квизы**:
  - `Courses → Courses / Lessons / Test questions`

### Процесс кандидата (end-to-end)

```mermaid
flowchart TD
  A[Кандидат зарегистрировался или создан по умолчанию] --> B[HR открывает User profiles]
  B --> C{user_type = candidate?}
  C -- нет --> D[Ок: это сотрудник]
  C -- да --> E[Проверить прогресс онбординга (Onboarding %)]
  E --> F[Проверить доступный контент (visible_for_candidates)]
  F --> G{Кандидат прошёл базовый минимум?}
  G -- нет --> H[Напомнить/дать ссылку на нужный модуль/курс]
  G -- да --> I[Convert to employee]
  I --> J[Назначить department + role (если нужно)]
  J --> K[AssignmentRule применит программу/курсы]
```

### 1) Как дать кандидату правильный доступ

#### Вариант A — дефолтный кандидат из `.env`
Если у вас в `.env` заполнены:
- `DEFAULT_CANDIDATE_EMAIL`
- `DEFAULT_CANDIDATE_PASSWORD`

то после команды:
- `python manage.py create_default_users --update`

кандидат создастся/обновится автоматически.

#### Вариант B — вручную через админку
1. `Users` → создать пользователя (email/username + пароль).
2. `Accounts → User profiles` → найти этого пользователя → выставить:
   - **`user_type = candidate`**
   - **`phone`** (для кандидата — обязательно)

#### Вариант C — саморегистрация
- Открыть **`/register/candidate/`**: email, телефон, пароль.
- На почту уходит ссылка подтверждения (**опционально**): кандидат **не блокируется** и может учиться сразу после регистрации.
- В админке в профиле смотрите **`email_verified_at`**. При необходимости: действие **Mark email as verified** или конвертация в сотрудника (там email тоже помечается подтверждённым).

---

### 2) Что именно “видно кандидатам” (флаги контента)

Сейчас кандидат видит только то, что помечено флагами:
- **OnboardingProgram**: `visible_for_candidates`
- **Course**: `visible_for_candidates`
- **Lesson**: `visible_for_candidates`

Проверка:
1. Откройте программу/курс/урок в админке.
2. Включите `visible_for_candidates=True` для того, что кандидат должен увидеть.

Важно:
- Для квиза кандидат должен иметь доступ **и к курсу, и к уроку** (иначе получит 404).

---

### 3) Мониторинг кандидатов

Откройте `Accounts → User profiles`:
- **Фильтр**: `user_type = candidate`
- **Колонки**:
  - `email_verified_at` — подтвердил ли email (саморегистрация)
  - `Onboarding %` — прогресс по онбордингу
  - `Last login` — когда заходил последний раз (если заходил)
  - `assigned_onboarding_program` — какая программа назначена

---

### 4) Конвертация кандидата в сотрудника

В `Accounts → User profiles`:
1. Отфильтруйте кандидатов
2. Выберите кандидата (или несколько)
3. Action: **Convert selected candidates to employees**

Что происходит:
- `user_type` меняется на `employee`
- группы `candidate/employee` синхронизируются
- применяется `AssignmentRule` (назначит программу/список курсов, если настроено)

После конвертации рекомендуется:
- выставить `department` и `role` в профиле (если ещё пусто)

---

### Быстрый чеклист HR (ежедневно/еженедельно)
- **кандидаты**: `User profiles` → фильтр `candidate` → проверить `Onboarding %` и `Last login`
- **контент**: новые/обновлённые курсы и онбординг → корректно выставлены `visible_for_candidates`
- **конвертация**: кандидаты, которые прошли минимум → convert + назначить dept/role

### Individual Learning Plans (ILP) — планы обучения сотрудникам

**Суть:** HR может создать персональный план обучения для конкретного пользователя и видеть прогресс.

#### Где в админке
- `/admin/` → `Courses → Individual learning plans`
- `/admin/` → `Courses → ILP items` (редко нужно — обычно хватает inline)

#### Как создать план (MVP)
1. `Courses → Individual learning plans` → **Add**
2. Заполнить:
   - **User** — кому назначаем план
   - **Title** — название плана
   - **Deadline** (опционально)
   - **Is active** — включено
3. Внизу добавить пункты (Inline `ILP items`):
   - `content_type`: `course` / `lesson` / `article`
   - `object_slug`: slug цели (пока используется как справочная ссылка)
   - `title`: отображаемое название пункта
   - `order`: порядок
   - `is_required`: обязательно/опционально
   - `deadline`: дедлайн пункта (опционально)
   - `is_completed`: отметка выполнения
4. **Save**

#### Что увидит пользователь
На странице профиля `/profile/` появится блок **My Learning Plan**:
- общий прогресс (в %)
- “Next up” — первый невыполненный пункт
- список первых пунктов плана

#### Мини-чеклист HR по ILP
- План активен (`is_active=True`)
- Пункты отсортированы по `order`
- Отмечаете `is_completed` по факту выполнения (пока вручную в админке)
