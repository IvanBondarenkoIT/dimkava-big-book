# HR FULL FUNCTIONAL CHECKLIST

> **Актуальная инструкция для HR:** см. **[HR_QA_ONE_PAGE.md](HR_QA_ONE_PAGE.md)**  
> (куда смотреть, сценарии, полный чеклист в одном файле).

Этот файл оставлен для совместимости со старыми ссылками.

Обновлено: 2026-08-19  
Назначение: пошаговый end-to-end сценарий для HR (краткий указатель).

## Подготовка (перед тестом)
- [ ] Есть тестовые аккаунты: candidate, employee, hr, admin.
- [ ] Доступны разделы `/analytics/hr/` и `/admin/`.
- [ ] В системе есть минимум 1 onboarding программа, 1 курс и 1 quiz-урок.
- [ ] У кандидата заполнен телефон.

Дальше проходите по разделам в [HR_QA_ONE_PAGE.md](HR_QA_ONE_PAGE.md).


## Шаг 1. Проверка входа и ролей
- [ ] Кандидат входит через `/login/` без ошибки.
- [ ] HR входит через `/login/` и открывает `/analytics/hr/`.
- [ ] HR имеет доступ к `/admin/`.
- [ ] Кандидат не имеет доступа к закрытым HR/Admin разделам.

## Шаг 2. Кандидатский путь обучения
- [ ] Кандидат открывает `/` и видит блок стартовых действий.
- [ ] Кандидат открывает `/onboarding/` и видит доступную программу.
- [ ] Кандидат открывает `/courses/` и видит доступные курсы.
- [ ] Кандидат заходит в урок и завершает его.
- [ ] На `/profile/` отражается движение прогресса.

## Шаг 3. Проверка квиза (one-attempt + HR unlock)
- [ ] Кандидат проходит квиз и отправляет ответы (1-я попытка).
- [ ] Повторный submit кандидата блокируется сообщением о lock.
- [ ] Текущий результат квиза остается сохраненным.
- [ ] HR в Hub `/analytics/hr/quiz-results/` видит тест → сдавших → карточку (балл, Answered/Unanswered, разбор); Allow retake на карточке; Task Stack `/analytics/hr/tasks/` показывает failed+locked.
- [ ] Кандидат снова может отправить квиз после unlock.
- [ ] После повторной отправки квиз снова блокируется.

## Шаг 4. HR Hub: кандидаты и конвертация
- [ ] В `/analytics/hr/candidates/` видно нужного кандидата.
- [ ] Видны ключевые поля (статусы/прогресс/контакты).
- [ ] При необходимости выполнено действие verify.
- [ ] Выполнено `convert to employee` для готового кандидата.
- [ ] После конвертации пользователь ведет себя как employee (доступы и интерфейс).

## Шаг 5. Visibility контроль
- [ ] В `/analytics/hr/visibility/` проверены флаги `visible_for_candidates`.
- [ ] Изменение флага приводит к ожидаемому изменению видимости у кандидата.
- [ ] Нет случайно открытого внутреннего контента для кандидатов.

## Шаг 6. Модерация
- [ ] В `/analytics/hr/comments/` обработана очередь pending комментариев.
- [ ] В `/analytics/hr/onboarding-feedback/` обработана очередь feedback.
- [ ] Approve публикации видно пользователям.
- [ ] Reject публикации не отображаются в публичных блоках.

## Шаг 7. Профиль и KPI
- [ ] У кандидата/сотрудника корректно отображаются KPI на `/profile/`.
- [ ] Отображается `public username` вместо email в пользовательских зонах.
- [ ] Badge showcase и certification progress отображаются без ошибок.

## Шаг 8. Финальный контроль
- [ ] Нет критичных ошибок в UI.
- [ ] Нет блокирующих проблем с доступами по ролям.
- [ ] Основные сценарии (candidate -> hr -> employee) проходят без ручных фиксов.

## Артефакты проверки
- [ ] Сохранены скриншоты по списку `SHOT-*`.
- [ ] Зафиксирован результат проверки: Passed / Passed with notes / Failed.
- [ ] Для замечаний создан список доработок с приоритетами.
