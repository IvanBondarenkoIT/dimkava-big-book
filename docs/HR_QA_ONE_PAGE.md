## Сценарий A — Кандидат сдал квиз плохо / нужна пересдача

1. Зайти: **Quizzes** → выбрать тест → человека.  
   URL: `/analytics/hr/quiz-results/` → тест → человек.
2. На карточке смотреть:
   - **Score %** и Passed / Failed  
   - **Answered / Unanswered** — сколько вопросов без ответа  
   - **Correct / Wrong** — разбор по вопросам (зелёный / красный)
3. Если нужна ещё попытка → кнопка **Allow retake**.
4. Кандидат (или сотрудник) снова открывает квиз и сдаёт.  
   После сдачи снова lock — снова нужен Allow retake при необходимости.

**Важно:** форму квиза нельзя отправить с пустыми вопросами. Старые попытки с низким % часто из‑за пропусков — смотрите Unanswered.

## Сценарий B — Правильные ответы в квизе (ключ)

1. Открыть квиз как HR → **Edit quiz** (или Content Editor).
2. У каждого вопроса выбрать **один** правильный вариант (радио Option 1–4).
3. Сохранить.

**Не просить IT запускать `load_courses`** — это может затереть ключи, которые вы проставили вручную.

Новый квиз в курсе: страница курса → **Add quiz** → заполнить вопросы (кнопка **Add question**) и ключ → Save. Новый обычный урок — **Add lesson**.

## Сценарий C — Комментарии

1. Сотрудник/кандидат пишет комментарий на странице **курса** (внизу).  
   Сотрудники также на статье wiki / новости.
2. Комментарий в статусе **Pending** — видит автор и HR, публично нет.
3. HR: `/analytics/hr/comments/` или Task Stack → **Approve** или **Reject**.
4. После Approve — комментарий виден всем на странице.

---

## Сценарий D — Кандидат → сотрудник

1. `/analytics/hr/candidates/` — найти человека.
2. Проверить: телефон, онбординг, ключевые курсы/тесты.
3. При необходимости **mark verified**.
4. **Convert to employee**.
5. После конвертации у человека открываются wiki, news и остальные разделы сотрудника.

---

## Сценарий E — Что видит кандидат

1. `/analytics/hr/visibility/` — флаги:
   - программа онбординга  
   - курс  
   - урок / квиз  
2. Включить только то, что нужно кандидатам.
3. Проверить под аккаунтом кандидата: `/onboarding/`, `/courses/`.

## Полный чеклист QA (раз в релиз / по запросу)

Отмечать по мере прохождения. Нужны аккаунты: **candidate**, **employee**, **hr**.

### Подготовка
- [ ] HR логинится на https://bigbook.dimkava.ge/login/
- [ ] Открывается `/analytics/hr/`
- [ ] Есть хотя бы 1 курс с квизом и 1 онбординг-программа

### Роли
- [ ] Кандидат **не** открывает `/analytics/hr/`, `/wiki/`, `/news/`
- [ ] HR открывает Hub и Admin

### Обучение кандидата
- [ ] `/` — стартовые действия
- [ ] `/onboarding/` — программа видна, шаг можно завершить
- [ ] `/courses/` — видны только курсы с visibility для кандидатов
- [ ] Урок завершён → прогресс на `/profile/`

### Квиз + retake
- [ ] Кандидат сдаёт квиз (все вопросы обязательны)
- [ ] Повтор без unlock — заблокирован
- [ ] HR: quiz-results → карточка → видны Answered / разбор
- [ ] Allow retake → кандидат сдаёт снова → снова lock
- [ ] Task Stack показывает failed+locked при необходимости

### Кандидаты
- [ ] Список в `/analytics/hr/candidates/`
- [ ] Verify (если нужно)
- [ ] Convert to employee → доступы как у сотрудника

### Visibility
- [ ] Смена флага меняет видимость у кандидата
- [ ] Внутренний контент кандидату не светится

### Модерация
- [ ] Комментарий с курса попадает в pending
- [ ] Approve → виден на странице; Reject → не виден публично
- [ ] Onboarding feedback: Approve / Reject работает так же

### Финал
- [ ] Нет критичных ошибок UI
- [ ] Результат: **Passed** / **Passed with notes** / **Failed**
- [ ] Замечания списком (что / приоритет)

## Частые вопросы

**Почему Score 39%, а в разборе всё зелёное?**  
Зелёные — только на **отвеченные** вопросы. Неотвеченные считались ошибкой (раньше можно было отправить частично). Смотрите **Unanswered**. Новые сдачи без пропусков.

**Сотрудник тоже не может пересдать без HR?**  
Да. После сдачи lock для всех; retake только через Allow retake (или Admin → UserProgress).

**Где править тексты курса / квиза?**  
Кнопка **Edit** на странице контента или `/edit/`… Не через «перезаливку курсов» на сервере.
